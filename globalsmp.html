GlobalSMP

A multi-server Minecraft network where the servers behave like one place. I'm lead developer on the core plugin: the Java layer every server loads, and the reason a player's account means the same thing wherever the proxy sends them.

The problem

A single Minecraft server is a closed world. One world file, one player list, one set of state sitting in memory. A network isn't. Put more than one server behind a proxy and everything a player thinks of as their account stops being local, and every server has to agree on it.

That agreement is what the core plugin provides. It's the piece every server loads, so the rules get written once instead of drifting apart across four separate codebases.

Architecture

Proxy in front, one database behind

One way in

Players connect to Velocity, never to a backend server directly. The proxy holds the connection open and hands it between servers, so moving between them is a transfer instead of a disconnect and a reconnect. It also means one address to remember and one place to control who gets in.

Behind it, every Paper server runs the same core plugin against the same MySQL database. The database is the source of truth. Servers hold state while you're on them, but they don't own it.

What's in the core plugin

Player data that follows you

Profiles load from MySQL on join and write back on quit or transfer, so what a player earned on one server is there on the next. Most of the real work is in the edge cases, like making sure a transfer never leaves two servers holding the same profile at once.

Shared rules

Permissions, ranks and the common gameplay systems live in the plugin rather than in each server's own config. Changing how something works is one change in one codebase, not four that slowly drift apart.

Room to add servers

Because the shared layer is a plugin and not per-server config, a new server joins the network by loading it and pointing at the same database. That's the reason for building the core first.

Why Paper and Velocity

Paper gives a wider and better documented API than plain Spigot, plus the performance work that starts to matter once more than a handful of people are on at the same time. Velocity is built for multi-server setups rather than retrofitted into them, and it copes with backend servers restarting underneath it without dropping everyone.

Neither is an exotic choice. Both are well-trodden, which is what I want underneath something people log into every day.
